# 🥔 界面规划

可视稿在 [`ui/mockup.html`](ui/mockup.html)，用浏览器直接打开。顶部一排按钮可以回放 22 个技能事件，看界面怎么反应；右上角可以切深色和槽位标注。它是静态页面，外框的颜色、圆角和字体取自 DSH 主题的真实数值，不是可运行的插件界面。界面代码从 M1 开始写。

## 原则

1. **长文本变成结构。** pstack 的 `ketchup`、`arena`、`hillclimb`、`show-me-your-work` 现在都往聊天里写长段落。它们的内容本来是待决事项、评分矩阵、折线和表格，界面按这个形状呈现。
2. **外框是 DSH 的，里面是土豆的。** 底色、边线、正文字体全部用宿主的 `--dsw-alias-*` 变量。pstack 自己只加五个颜色、一套标题字体和四个图形，见下一节。不引入组件库，不用 iframe。
3. **章只盖在判定上。** 界面上的每个章都对应一次判定。实线章是运行时判的，虚线章是代理自己报的。代理写的普通文字不盖章。用户扫一眼就能分清哪些话有运行时作证。
4. **只加不盖。** DSH 的槽位分两种：列表型是追加，单座和键控型会顶替宿主自带的界面。本规划只用追加型，唯一的键控注册是给自己的工具名画卡片。内置 `bash` 卡片不动。
5. **界面能做的，代理也能做；放权的事只有人能做。** 面板里“以 B 为底”这类操作同时暴露成代理工具。关闭 TDD 门禁、批准强推只属于用户。

## 视觉语言

上游给 poteto-mode 定的图标是王冠，颜色是黄色。这里把它落成一颗戴王冠的土豆，再从土豆身上取其余的图形。

### 四个图形

| 图形 | 代表什么 | 状态 |
|---|---|---|
| 土豆 | 这个会话的 pstack 状态 | 生的：没开 poteto-mode。戴王冠：模式开着。沾番茄酱：有事等你。整颗金色：playbook 全部做完。 |
| 薯条 | playbook 的一个步骤 | 空心：没做。半截金色：正在做。金色：做完。每根略微歪一点，不排成进度条。 |
| 芽眼 | 一条原则，共 24 条 | 空心：没读。实心：这个会话读过它的技能文件。红色：回复里引用了但没读过。 |
| 章 | 一次判定 | 实线：运行时判的。虚线：代理报的。斜 3 度，落下时有一拍动效。 |

土豆是物件，不是吉祥物：没有脸，不说话，不做表情。它只靠皮色、王冠和番茄酱三样东西表达状态。

`🥔` 这个 emoji 用在纯文本的地方：拦截理由、审批理由、README、命令行输出。图形界面里用 SVG 土豆，因为 emoji 在各个系统上长得不一样，也没法戴王冠。

### 五个颜色

| 名字 | 浅色 | 深色 | 只用在 |
|---|---|---|---|
| 金 | `#F2C230` | `#F2C230` | 做完的步骤、保留的改动、王冠 |
| 赤褐 | `#7A4E24` | `#D9A968` | 土豆的轮廓、读过的芽眼 |
| 番茄酱 | `#D7261E` | `#FF6257` | 拦下、复跑成立的问题、等你决定 |
| 细葱 | `#2E7D46` | `#63CC84` | 通过、转绿 |
| 紫薯 | `#6B4C9A` | `#B397EA` | 跨厂商、编排动作（重派、替换） |

灰色用宿主的 `text-tertiary`，表示丢弃、回滚、无输出。没有第六个颜色。厂商不单独配色，用文字写出来。

### 字体

标题、数字和章用系统的圆体：`ui-rounded`，回退到 `SF Pro Rounded`、`Hiragino Maru Gothic ProN`、`Nunito`，最后是宿主字体。圆体让 pstack 的东西在宿主的界面里一眼能认出来，又不需要加载字体文件。正文用宿主字体。等宽字体只用于命令和代码。

### 动效

没有事件就不动。三种动效，各对应一件事：

- 章落下，260 毫秒。只在判定产生的那一刻播放一次，切换分页回来不重播。
- 变化的地方闪一圈金边，900 毫秒，告诉用户看哪里。
- 输入框上方的提示条停 5 秒，写明是哪个技能、发生了什么、判定是什么。

系统开了“减少动态效果”时三种都关掉，内容照常出现。

### 文字

章不超过 4 个汉字。同一个判定在所有地方用同一个词：折线、表格和提示条里都叫“保留”，不会一处叫“保留”一处叫“接受”。拦截信息写三件事：拦了哪条命令、为什么、应该怎么写。

## 一、Playbook 进度条

输入框上方的一条窄带。没有激活 playbook 时不占位。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 🥔 Bug fix   ▰ ▰ ◧ ▱ ▱ ▱    3/6 规划修复      ● 红灯已见    拦下 1 次     │
└──────────────────────────────────────────────────────────────────────────┘
```

- 最左是土豆，四种状态见上一节。
- playbook 名称，悬停显示它的立场句，比如 “You own this task. Plan, review, verify.”
- 每根薯条是一个步骤，悬停显示步骤原文。
- 右侧是门禁。TDD 有四态：未开、等红灯、红灯已见、已转绿。护栏显示这个会话拦了几次。
- 点整条打开右侧栏的 Playbook 页。

**加载过程。** 用户输入 `/poteto-mode` 后，进度条分三拍出现，每拍对应一件真实发生的事，不用假进度：技能正文被读到时，土豆戴上王冠；playbook 文件被读到时，生薯条排出来；代理报第一步时，第一根开始变金。任务不匹配任何 playbook 时名称显示 “figure-it-out”，对应 pstack 的兜底路由。

## 二、右侧栏面板

一个标签页，四个分页。

### Playbook 页

```
🥔  Bug fix
    You own this task. Plan, review, verify.
──────────────────────────────────────────────────────
目标  列表在空闲时保持不动。最小改动是修掉触发漂移的计时器。
──────────────────────────────────────────────────────
 ▰  在对应界面上自己复现
 ▰  二分定位原因                                 [why]
 ◧  规划修复，跨函数边界先 architect        [architect]
 ▱  在同一界面上验证
 ▱  失败的复现先于修复提交                        [tdd]
 ▱  Opening a PR

原则                              这个会话读过 5 条，共 24 条
 核心   ● ● ○ ○ ○ ○ ○ ○ ○ ○
 架构   ○ ● ○ ○ ○ ○
 验证   ● ● ○ ○ ○
 委派   ○ ○
 元     ○

门禁
 TDD    [红灯已见]   pnpm test useAutoScroll 退出码 1，生产代码已放开
 命令   [拦下 1]     git add -A
 强推   [要问你]     受保护分支是 main 和 release
```

- “目标”是 poteto-mode 要求的第一件事：重述用户的目标和满足它的最小改动。它固定在页面顶部，后面每一步都对着它。
- 步骤右侧的标签是这一步点名的技能。读过的是金底，没读过的是虚线框。
- 两种提示会插在原则和门禁之间：引用了没读的原则（红），两个修法败在同一关（金）。

### 面板页（arena、interrogate、swarm）

arena 的主体是评分矩阵，列是候选，行是评分项，被选为底的一列铺金色底。

```
Arena
修复 useAutoScroll 的空闲重排

                              A                B                C
                        claude-opus-5-5   deepseek-v4    gemini-4-neon
只改启动条件，不动调度        3                5                –
有会失败的回归测试            5                4                –
新消息到达时仍贴底            5                5                –
改动行数少                    3                4                –
合计                         16               18                –

[跨厂商]  裁判是 anthropic 的 claude-opus-5-5，主代理是 deepseek。
          它推荐以 B 为底，把 A 的回归测试嫁接过来。

                          [看 A 的 diff]  [看 B 的 diff]  [以 B 为底]
```

- 裁判那一行写明它是谁、和主代理是不是同一家。厂商来自 [`model-routing.ts`](../src/core/model-routing.ts)。只有一家厂商时写“跳过了裁判：没有别家的模型”。主代理的厂商认不出时写“厂商校验没跑”。
- 候选席位有五态：排队、启动中、运行中（带已用时间）、交卷、无输出。排队是真实状态，DSH 的子代理满 8 个之后不会自动排，插件自己排。
- 点候选可以打开它的子会话。子代理的对话视图用 DSH 自带的，不重做。

interrogate 在矩阵下面列结论。复跑成立的展开为命令和输出，盖“成立”。被丢弃的不展开，只写每个评审员丢了几条和原因。一条都不成立时写 “no verified findings”，不留空白。

swarm 显示切片表，每行一个 `PASS`、`ISSUES` 或 `BLOCKED`。结果里缺 SHA 或做法的那一行盖“重派”，第二次还缺就盖“缺口”，缺口不算通过。

```

越低越好，每次取 5 个样本的中位数

 120 ┤       ┗━●━━━━━○━━━┓
 100 ┤                   ┗━●━━━━━○━━━┓
  80 ┤                               ┗━●
  60 ┤▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒   目标 71 以下
     └───1───────2───────3───────4───────5───6

 −37%  目标 −50%   6  至少 10         3 保留  3 回滚

 6  把埋点移出启动路径          104     89   [保留 −14%]
```

- 金色的台阶线是“当前保留下来的最好成绩”，只在保留时下一级。实心金点是保留，空心点是回滚。每个点带一条竖线表示噪声。
- 回滚原因直接来自内核的枚举：样本不足、基准报错、工作量变了、门禁变红、变差、在噪声内。
- 停止条件的两半并排显示，因为 pstack 要求目标和最少尝试次数同时满足。
- 连续三次回滚时出现平台期提示。测量脚本在冻结之后变了，右上角的章变成红色的“基准被动过”。

### 记录页（show-me-your-work）

决策日志的表格，列与 pstack 的 TSV 一致。证据列可以点：commit 打开 diff，`file:line` 打开文件。没有证据的格子盖“缺”。底部是 Attention 区，写明由哪家的哪个模型复核。可以导出 TSV，格式与 `log.sh` 写出的相同。

## 三、聊天里的卡片

只给插件自己的工具画卡片。卡片没有四周的边框，左边一条竖线表示种类：金色是编排，赤褐是 Comment Sicko，番茄酱色是等你决定。

- **`pstack_arena`**：标题、六段阶段轨（定题、扇出、交叉评审、选底、嫁接、验证）、每个席位的模型、厂商和章。完成后收起为一行。
- **`pstack_no_comments`**：Comment Sicko 的报告。保留它那句 “Yes... Ha ha ha... Yes!”，下面三个数字：删掉的注释、要改代码的 `MUST KILL`、留给用户看的 `REVIEW`。
- **`pstack_attempt`**：一行，显示假设、前后数值和章。
- **`pstack_ketchup`**：见下节。

护栏的拒绝不需要新卡片。它显示在内置 `bash` 卡片的错误行里，文字以 🥔 开头，包含被拦的命令、原因和改法。

## 四、等你决定（ketchup）

`/ketchup` 现在的产物是一段回复。它的结构其实是固定的，插件把它变成一个工具调用，卡片就是面板：

```
┃ 2 件事等你决定
┃
┃ 合并这个修复？
┃ 我的建议是合并。
┃   变化  空闲时列表不再每 750ms 抖一下。
┃   证据  原复现脚本从失败变为通过，失败的测试排在修复前面。
┃   风险  低。只改了一个计时器的启动条件。
┃                                         [先看 diff]  [合并]
┃ ─────────────────────────────────────────────────────────
┃ 强推 fix/idle-scroll 到远端？
┃ 我的建议是不推，改推到新分支。
┃   代价  强推会覆盖远端上 1 个不在本地的提交。
┃                                   [仍然强推]  [推到新分支]
```

每项的字段就是 ketchup 技能要求的那几样：要用户做的决定、代理的建议、对用户的变化、证据、风险。在几个选项里挑的那种决定不单列风险，写每个选项的代价。文字照 ketchup 的要求用大白话，不出现哈希和路径。

按钮点击后以用户消息的形式发回，所以决定会进入会话日志。批准类按钮只在界面上有，不提供给代理。

## 五、会话列表

长时间运行和多会话并行时，用户最需要知道哪个会话在等自己。

- 行尾是小土豆加步骤数，比如 `3/6`。
- 有事等你的会话显示番茄酱色的计数。
- 夜间运行和已落地各有一个小灯。
- 悬浮卡多一节：playbook 名称、当前步骤、待决事项。

## 六、配置界面

替代 `/setup-pstack` 写 Markdown 文件的做法。

- **护栏行**：受保护分支和发布命令正则的编辑框，下面带一个试运行框，输入一条命令立刻显示拦下、要问你还是放行。内核是纯函数，同一份分类器直接在浏览器里跑。
- **面板行**：每个角色的席位列表。模型从 DSH 的模型目录里选，旁边显示自动认出的厂商，可手动改。预算选 large、medium、small 三档。列表下方实时显示“这个面板有 2 家厂商”和“裁判会是谁”。

## 七、技能事件对照表

pstack 的每个技能都有几个只属于它的时刻。下表列出每个时刻运行时怎么知道、界面上发生什么。

“谁说的”一列决定章是实线还是虚线。**运行时**表示插件自己看到或算出来的：工具管线的钩子、命令的退出码、子代理的返回、内核函数的结果。**代理**表示代理通过插件的工具报上来的，运行时没法独立核实。

目前验证过的信号只有三个：命令否决、进入审批、技能提供者，都在真实的 DSH 0.2.2-rc.5 里跑过。标了内核函数名的判定逻辑有单元测试，还没接到 DSH。其余信号来自读 DSH 源码，没有运行过，接入时可能要改。

“稿”一列打勾的可以在可视稿顶部回放。

### poteto-mode 与原则（M1）

| 认出 playbook | 运行时 | 读了 `playbooks/<名>.md`，`parsePlaybook` 切出步骤 | 生薯条排出来，名称和立场句出现 | ✓ |
| 没有匹配的 playbook | 运行时 | 读了 `figure-it-out` | 名称显示 figure-it-out，没有薯条 | |

| 做完一步 | 代理 | `pstack_step` | 一根薯条变金。全部做完时土豆整颗变金 | ✓ |

## 八、实现约束

- **客户端打包格式。** DSH 的客户端模块是 `window.__ModuleLoader__.load({ id, factory(require) })` 形式。产出这种格式的构建预设没有随 DSH 发布，仓库外的包要自己打。M1 的第一项工作是用 esbuild 把 React 源码打成这个格式，`react`、`@deepseek-ai/dsh-client-ui-slots` 等宿主已提供的模块声明为外部依赖。
- **不加载宿主的组件包。** DSH 的实践文档明确要求不要 `require('@deepseek-ai/dsh-client-ui-primitives')`，因为它会不通知就变。按钮、开关、提示这些控件照宿主的样式自己写。
- **组件拿不到 Cordis 上下文。** 数据通过槽位属性里的选择器钩子读，操作通过注册时的 `inject` 回调传进去。
- **不自己推事件。** DSH 转发给客户端的 Host 事件是固定名单，第三方加不进去。上表的每个事件都先落进投影，再由投影的 `wire.view` 带到客户端。提示条由客户端比较前后两次投影得出，不是服务端推的。
- **没有“技能已加载”事件。** 只能从 `tools/result` 里看代理读了哪个文件。代理不读文件直接凭记忆做，界面就不会亮，这正好是引用审计要抓的情况。
- **卡片要能独立于面板成立。** `headless`、`sdk`、`acp` 这些配置没有 Web 界面，工具结果的文字内容必须自己就完整。界面是增强，不是唯一出口。
