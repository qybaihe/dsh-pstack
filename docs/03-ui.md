# 界面规划

可视稿在 [`ui/mockup.html`](ui/mockup.html)，用浏览器直接打开。它是静态页面，颜色、圆角和字体取自 DSH 主题的真实数值，用来对齐布局和信息密度，不是可运行的插件界面。界面代码从 M1 开始写。

## 原则

1. **长文本变成结构。** pstack 的 `ketchup`、`arena`、`hillclimb`、`show-me-your-work` 现在都往聊天里写长段落。它们的内容本来是待决事项、评分矩阵、折线和表格，界面按这个形状呈现。
2. **看起来就是 DSH 的一部分。** 只用宿主的 `--dsw-alias-*` 主题变量，不引入组件库，不用 iframe。文字走客户端 locale 服务，中英文都提供。
3. **只加不盖。** DSH 的槽位分两种：列表型是追加，单座和键控型会顶替宿主自带的界面。本规划只用追加型，唯一的键控注册是给自己的工具名画卡片。内置 `bash` 卡片不动，护栏的拒绝信息就显示在它原本的错误行里。
4. **界面能做的，代理也能做；放权的事只有人能做。** 面板里“采用这个候选”这类操作同时暴露成代理工具。关闭 TDD 门禁、批准强推只属于用户。

## 界面与槽位

DSH 没有终端界面，也没有叫 status bar 的槽位。下表的槽位名都来自 DSH 的槽位目录。

| 界面 | 槽位 | 数据来源 | 里程碑 |
|---|---|---|---|
| Playbook 进度条 | `conversation.input.dock` | `pstackPlaybook` 投影 | M1 |
| poteto-mode 常驻开关 | `conversation.input.left` | 同上 | M1 |
| 新会话里选 playbook | `conversation.hero.options` | 静态目录 | M1 |
| 右侧栏 pstack 面板 | `sidebarRightTabs` + `sidebar.right.pane.tab` | 各投影 + `connection.rpc` | M1 起逐页加 |

## 一、Playbook 进度条

输入框上方的一条窄带。没有激活 playbook 时不占位。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ● Bug fix   ━━━━━ ━━━━━ ▬▬▬▬▬ ───── ───── ─────   3/6 规划修复          │
│                                              TDD 红灯已见 · 护栏拦截 2   │
└──────────────────────────────────────────────────────────────────────────┘
```

- 左侧是 playbook 名称，悬停显示它的立场句，比如 “You own this task. Plan, review, verify.”
- 中间每段是一个步骤，三种状态：完成、进行中、未开始。悬停显示步骤原文。
- 右侧是门禁状态。TDD 有四态：未开启、等红灯、红灯已见、已转绿。护栏显示本会话的拦截次数。
- 点击整条打开右侧栏面板的 Playbook 页。

**加载过程。** 用户输入 `/poteto-mode` 后，进度条分三拍出现，每拍对应一件真实发生的事，不用假进度：技能正文注入时出现名称；插件识别出 playbook 时步骤段落展开；步骤写入完成时第一段亮起。识别失败（任务不匹配任何 playbook）时显示 “figure-it-out”，对应 pstack 的兜底路由。

## 二、右侧栏面板

一个标签页，四个分页。分页用宿主的分段控件样式。

### Playbook 页

```
Bug fix                                             步骤 3 / 6
You own this task. Plan, review, verify.

 ✓ 1  在对应界面上自己复现
 ✓ 2  二分定位原因                                    why
 ▶ 3  规划修复                                   architect
   4  在同一界面上验证
   5  失败的复现先于修复提交                           tdd
   6  Opening a PR

原则                                        本会话读过 5 / 24
 核心      ● ● ○ ○ ○ ○ ○ ○ ○ ○
 架构      ○ ● ○ ○ ○ ○
 验证      ● ● ○ ○ ○
 委派      ○ ○
 元        ○
```

- 步骤右侧的标签是该步骤点名的技能。读过的实心，没读过的空心。
- 原则区每个点是一条原则。回复里引用了没读过的原则时，对应的点标红，这就是引用审计的界面形态。

### 面板页（arena、interrogate、swarm）

arena 的主体是评分矩阵，列是候选，行是评分项。

```
Arena · markdown 渲染器                裁判 google/gemini-4-neon · 厂商校验已执行

                      候选 A            候选 B            候选 C
                      anthropic         deepseek          google
                      claude-opus-5-5   deepseek-v4       gemini-4-neon
                      ✓ 完成 4m12s      ✓ 完成 2m50s      ✕ 无输出
边界清晰                 4                 5                 –
API 面积                 3                 5                 –
可扩展                   5                 3                 –
测试覆盖                 4                 4                 –
                      ─────             ─────
                        16               17  ← 裁判推荐
                     [看 diff]         [看 diff]
```

- 每列顶部显示厂商、模型和推理强度。厂商来自 [`model-routing.ts`](../src/core/model-routing.ts) 的判断，判断不出时显示 “未知” 并提示去配置里标注。
- 右上角写明裁判是谁、厂商校验是否执行。只有一家厂商时显示 “已跳过裁判：没有其他厂商的模型”。
- **运行中的状态。** 候选列有五态：排队（超过 8 个并发时）、启动中、运行中（带已用时间）、完成、无输出。排队是真实状态，因为 DSH 的子代理容量满了不会自动排。
- 点候选可以打开它的子会话。子代理的对话视图用 DSH 自带的，不重做。

interrogate 显示结论列表：通过复跑的结论展开为命令、输出、违背了意图的哪一点、哪些评审员发现了它；被丢弃的只显示每个评审员丢了几条和原因。swarm 显示切片表，每行 `PASS`、`ISSUES` 或 `BLOCKED`，缺口单列。

### 实验页（hillclimb）

```
首屏渲染 p50（越低越好）                          基准已冻结 a3f9…

 160 ┤ ○                                    ── 基线 142ms
 140 ┤───●───────○───────────────────────
 120 ┤       ●
 100 ┤               ○   ●
  80 ┤                       ●  ← 89ms（−37%）
  70 ┤· · · · · · · · · · · · · · · · · · ·  目标 71ms（−50%）
     └─┬───┬───┬───┬───┬───┬───
       1   2   3   4   5   6

 目标 −37% / −50%        尝试 6 / 至少 10        保留 3 · 回滚 3

 #  假设                              前     后     判定
 6  把 X 移出启动路径                  104    89    保留 −14%
 5  缓存布局测量                       104   103    回滚：在噪声内
 4  延迟加载图标                       121   104    保留 −14%
```

- 实心点是保留，空心点是回滚。每个点带一条竖线表示噪声带。
- 回滚原因直接来自内核的枚举：样本不足、基准报错、工作量变了、门禁变红、变差、在噪声内。
- 停止条件的两个部分并排显示，因为 pstack 要求目标和最少尝试次数同时满足。

### 记录页（show-me-your-work）

决策日志的表格，六列与 pstack 的 TSV 一致。证据列可以点：commit 打开 diff，`file:line` 打开文件。没有证据的行有标记。底部是 “Attention” 区，首行是 `reviewed by <model>`，对应 pstack 要求的跨厂商复核。可以导出 TSV，格式与 `log.sh` 写出的相同。

## 三、聊天里的卡片

只给插件自己的工具画卡片。

- **`pstack_arena` 等编排工具**：一张紧凑卡片，显示各席位的实时状态和 “打开面板” 按钮。完成后收起为一行摘要。
- **`pstack_attempt`**：一行，显示假设、前后数值和判定。
- **`pstack_ketchup`**：追赶面板，见下节。

护栏的拒绝不需要新卡片。它显示在内置 `bash` 卡片的错误行里，文字已经包含被拦的命令、原因和改法。

## 四、追赶面板（ketchup）

`/ketchup` 现在的产物是一段回复。它的结构其实是固定的：一句话总览、发生了什么、等用户决定的事项。插件把它变成一个工具调用，卡片就是面板：

```
┌ 3 件事等你决定 ──────────────────────────────────────────────┐
│                                                              │
│ 合并这 2 个 PR？                         我的建议：都合并     │
│  · 搜索加索引        用户搜索从 2 秒降到 0.2 秒               │
│    证据：基准前后各跑 5 次    风险低：只加索引                 │
│  · 修滚动漂移        空闲时不再每 750ms 抖一下                │
│    证据：原复现脚本通过      风险低：只改一个计时器            │
│                                    [ 都合并 ]  [ 逐个看 ]     │
│                                                              │
│ 强推 feature/search 到远端？              我的建议：先别推     │
│    会覆盖 2 个别人的提交                                      │
│                                    [ 不推 ]  [ 仍然强推 ]     │
└──────────────────────────────────────────────────────────────┘
```

每项的字段就是 ketchup 技能要求的那几样：要用户做的决定、代理的建议、对用户的改变、证据、风险。按钮点击后以用户消息的形式发回，所以决定会进入会话日志。批准类按钮只在界面上有，不提供给代理。

## 五、会话列表

长时间运行和多会话并行时，用户最需要知道哪个会话在等自己。

- 行尾徽标：playbook 的字母标，加三种状态点——运行中、等你决定、已完成。
- 悬浮卡多一节：playbook 名称、步骤 n/m、待决事项数。

## 六、配置界面

替代 `/setup-pstack` 写 Markdown 文件的做法。

- **护栏行**：受保护分支和发布命令正则的编辑框，下面带一个试运行框，输入一条命令立刻显示否决、审批还是放行。内核是纯函数，同一份分类器直接在浏览器里跑。
- **面板行**：每个角色的席位列表。模型从 DSH 的模型目录里选，旁边显示自动判断的厂商，可手动改。预算选 large、medium、small 三档。列表下方实时显示 “这个面板覆盖 2 家厂商” 和 “裁判将是谁”。

## 七、实现约束

- **客户端打包格式。** DSH 的客户端模块是 `window.__ModuleLoader__.load({ id, factory(require) })` 形式。产出这种格式的构建预设没有随 DSH 发布，仓库外的包要自己打。M1 的第一项工作是用 esbuild 把 React 源码打成这个格式，`react`、`@deepseek-ai/dsh-client-ui-slots` 等宿主已提供的模块声明为外部依赖。
- **不加载宿主的组件包。** DSH 的实践文档明确要求不要 `require('@deepseek-ai/dsh-client-ui-primitives')`，因为它会不通知就变。按钮、开关、提示这些控件照宿主的样式自己写。
- **组件拿不到 Cordis 上下文。** 数据通过槽位属性里的选择器钩子读，操作通过注册时的 `inject` 回调传进去。
- **不自己推事件。** DSH 转发给客户端的 Host 事件是固定名单，第三方加不进去。实时状态走投影的 `wire.view`。
- **卡片要能独立于面板成立。** `headless`、`sdk`、`acp` 这些配置没有 Web 界面，工具结果的文字内容必须自己就完整。界面是增强，不是唯一出口。
