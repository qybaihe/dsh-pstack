# 路线图

每个里程碑以一条能重跑的检查结束。没有这条检查通过，不算完成。

## M0 骨架、技能、命令护栏 —— 已完成

- pstack 按固定 commit 入库，同步脚本可重跑。
- 内核八个模块：命令策略、TDD 状态机、实验判定、决策日志、模型路由、playbook 解析、原则引用、技能文件解析。
- 两个可加载的插件：`pstack-skills`、`pstack-guard`。
- 文档：分析、架构、界面规划。

**检查**

```bash
pnpm run check
```

```bash
pnpm run smoke
```

`check` 是类型检查、79 个单元测试和构建。`smoke` 把构建产物装进一个临时的 DSH 配置，在真实运行时里确认：58 个技能可查，`git add -A` 和草稿 PR 被否决，强推进入审批，按路径暂存放行。它不调用模型，也不执行任何 shell 命令。

已在 DSH 0.2.2-rc.5 上通过。0.2.3-alpha.1 没测成：这台机器上 `npx @deepseek-ai/dsh@alpha --version` 自身就因缺少模块导出而退出，问题出在 DSH 的启动阶段，还没走到加载插件。

**这一版没做的**：`ask` 的弹窗没有在 Web 界面里实际点过，冒烟只验证到审批请求确实发出。没有用真实模型跑过一次完整的 `/poteto-mode` 会话。

## M1 poteto-mode 成为一等公民

- 根行 `pstack`：登记 5 个 Agent Preset，注入 DSH 适配说明（把技能文本里的 Cursor 工具名对到 DSH 的工具名）。
- `pstack-playbook`：识别 playbook，写入步骤，babysit 期间把强推从审批升级为否决，investigation 期间收掉写工具。
- `pstack-tdd`：`/tdd on`、`/tdd off` 命令和写入门禁。
- `pstack-ledger`：决策日志工具，结束本轮前的原则引用审计。
- 客户端：打包链路、进度条、右侧栏的 Playbook 页和记录页、会话列表徽标。

**检查**：冒烟脚本增加三项——登记的 preset 都能解析；门禁开启后对 `src/a.ts` 的写入被否决、对 `src/a.test.ts` 的写入放行；一次红灯测试结果之后同一写入放行。另用真实模型跑一次 Bug fix playbook，在界面里核对进度条与实际步骤一致。

**先要验证的未知项**：Web 配置里 `tool-todo` 挂在 preset 内部，Host 层插件能否向它的列表写入步骤。验证不通过就改为只在自己的面板里显示步骤。

## M2 面板：arena、interrogate、swarm

- `pstack-panel`：席位解析与校验、并发队列、worktree 生命周期、跨厂商裁判、interrogate 的复跑验证。
- 三个编排工具和它们的卡片，右侧栏的面板页。
- 护栏行和面板行的配置界面。

**检查**：用一个故意带缺陷的小仓库做夹具。interrogate 必须报出那个缺陷并附上能复现的命令；一条编造的结论（命令实际通过）必须被丢弃。用户只配置一家厂商时，arena 的结果必须写明裁判已跳过。

## M3 实验台：hillclimb

- `pstack-bench`：基准冻结、采样、判定、按文件提交或回滚、冻结期间的写入否决。
- `pstack_attempt` 工具和卡片，右侧栏的实验页。

**检查**：夹具仓库带一个可调延迟的基准。一次真改进被保留并产生一个只含改动文件的提交；一次噪声内的改动被回滚且工作区干净；一次“少干活”的改动因 `work` 变化被回滚；冻结后对基准文件的写入被否决。

## M4 无人值守与自演进

- `pstack-autopilot`：定时巡检、目标驱动、卡死检测与替换。
- 追赶面板（`pstack_ketchup`）。
- `/correct` 产出的规则写回护栏配置并热重载。
- benny：依赖实验性的 webhook 运行时，等它稳定再做。

**检查**：一个被人为挂起的子代理在设定时间内被发现并替换，日志里有对应的一行。写回一条新规则后不重启 DSH，冒烟探针里对应命令的判定发生变化。

## 之后

内核不依赖 DSH，所以同一套规则可以再接一个 Pi 扩展。Pi 的扩展点（`pi.on("tool_call")`、状态栏组件）与本仓库的 Host 层一一对应，届时新增的只有接线代码。
